# Rank inputs and result contracts

1. **Strict input policy:** `process_input_table` requires the feature column plus the active metric columns. Signed-log ranking requires fold change and probability; precomputed ranking requires `existing_rank_metric_column_name`. Missing/blank identifiers, missing/nonnumeric/nonfinite metrics, complex metrics, and probabilities outside `[0,1]` raise `ValueError` before rank CSV writing. Messages identify the affected column and a bounded sample of row labels. Numeric strings are accepted. The caller's DataFrame is unchanged.

2. **Identifier handling:** Actual null identifiers are rejected before string conversion. Nonblank identifiers retain their text; whitespace is not silently stripped from otherwise valid names. If multi-name splitting yields a missing/blank selected identifier, the call fails instead of dropping it. Existing flag precedence is retained: keep-first occurs before explode when both flags are true. A literal string such as `"nan"` is not treated as an actual missing value.

3. **Scientific behavior preserved:** Signed ranking remains `sign(fold change) * -log10(probability)`. Exact zero probabilities still use `np.nextafter(0, 1)`. Duplicate identifiers still retain the largest absolute rank, and existing tie ordering remains unchanged. These policies require separate scientific review; strict validation does not resolve tied-rank or duplicate-aggregation findings.

4. **Permutation counts:** Both single- and multiple-collection entrypoints require a positive integral count. Positive integer-valued floats and decimal integer strings accepted by GSEApy remain accepted; zero, negative, fractional, nonfinite, boolean and invalid counts fail before processing. Defaults remain 100 in the wrapper. There is no implicit score-only mode.

5. **Supported single-run options:** `run_single_gsea_prerank(..., **kwargs)` now forwards `outdir`, `pheno_pos`, `pheno_neg`, `weight`, `ascending`, `figsize`, `format`, `graph_num`, and `no_plot` to GSEApy. Unknown names raise `TypeError` rather than being ignored. Omitted options are not injected, so GSEApy defaults remain effective. In particular, `weight=0` is honored. The multiple-collection wrapper's scientific parameters are unchanged; this change does not add arbitrary keyword forwarding to it.

6. **Return modes:** The default multiple-collection call still returns `None`; `return_single_pre_res=True` still returns the last result, including for multiple collections. New `return_all_pre_res=True` returns a list of every GSEApy result in input collection order. A list preserves duplicate collection names without overwriting a mapping entry. The two return flags are mutually exclusive. Empty collection lists raise before rank generation. All-results mode retains every result in memory, so callers should account for collection size.

7. **Adjustment family and outputs:** FDR remains calculated separately for each GSEApy collection run. It is not a global correction across a concatenated set of CSVs. Logs say `reported terms` after the matched-gene-count filter, not `significant terms`. Existing result CSV schemas and naming rules remain unchanged.

8. **Batch metadata sidecar:** Successful saved batches additionally write `<file_base_name>.<GSEA_run_filename_tag>.run_metadata.json`. It records effective wrapper parameters, per-collection family identifiers (`collection_1`, etc.), original labels, allocated result filenames, and weight/ascending reported by each GSEApy result (null if unavailable). Family identity is local to this batch and remains distinct even for duplicate collection labels. Output filenames match collision suffix allocation. The sidecar is deterministic for unchanged inputs/settings and adds no timestamp. This is a scope/parameter record, not a complete provenance manifest with input/reference hashes; fuller provenance belongs to roadmap plan 07.

9. **Failures and no-save:** Schema, result-write and metadata-write failures propagate. `save_table_output=False` produces no rank/result/metadata files and still supports the all-results return. A failed saved batch may leave earlier output files; transactional batch publication is outside this change. Existing files from prior runs can still be replaced.

10. **Metabolite annotations:** `metabolon_chemical_annotation_to_pathway_table` removes actual null and blank members from each selected annotation column before converting retained members to strings. Original member order, duplicates and literal `"nan"` text are retained. No new Excel engine or dependency is installed.

11. **Example:** With an existing DataFrame `data` containing `feature_name` and `rank`, and dictionaries `set_a` and `set_b`, call `run_gseapy_prerank_multiple_term_collections(data_df=data, list_of_term_collections=[set_a, set_b], rank_metric_calc_flavor='use_column_key', existing_rank_metric_column_name='rank', save_table_output=False, return_all_pre_res=True)`. The returned list follows `[set_a, set_b]` order; enrichment uses the existing wrapper defaults unless supplied otherwise.
