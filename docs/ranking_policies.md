# Ranking policies

1. **Canonical order:** `process_input_table` and the batch wrapper sort rank values descending, then feature IDs in case-sensitive lexical string order ascending. No jitter or numeric offset is added. This makes tied ranks independent of input row order. Numeric IDs have already been converted to strings, so `"10"` sorts before `"2"`. Whitespace in valid identifiers is retained. Exact zero ranks use positive-zero representation so `-0.0` and `0.0` serialize identically; their numerical values and rank ordering semantics are unchanged.

2. **GSEApy ordering and direct calls:** `run_single_gsea_prerank` now supplies `ascending=None` unless explicitly overridden. GSEApy therefore preserves the supplied rank order. This is an intentional behavioral change for direct callers: prepare ranks with `process_input_table`, or provide an already ordered DataFrame, Series, or rank file. Explicit `ascending=True` or `False` still asks GSEApy to sort and opts out of the wrapper's canonical tie-order guarantee. The batch wrapper uses the prepared order. GSEApy may still emit its generic warning that tied values have arbitrary order; the wrapper's canonical preparation fixes that order without suppressing GSEApy diagnostics.

3. **Duplicate identifiers:** The default remains maximum absolute rank per feature ID. Duplicate counts and the number of IDs with both positive and negative ranks are logged. Opposing-sign duplicates additionally emit a `RuntimeWarning`; a uniquely larger absolute rank determines the retained direction. Equal-magnitude opposite-sign **maxima** raise `ValueError` before writing the rank CSV or running GSEA. Equal opposite-sign values below a larger maximum do not raise. Identical signed maxima are interchangeable. Zero is neither positive nor negative for conflict counting. Resolve ambiguous estimates upstream rather than relying on input order to choose a direction.

4. **Explicit duplicate retention:** `make_feature_names_unique=False` still retains all rows, including opposite-sign maximum ties, and warns about directional conflicts. Prepared rows remain canonically sorted. GSEApy can rename duplicate IDs during loading; retaining duplicates remains a deliberate caller choice and is not a new biological aggregation policy.

5. **Zero probabilities:** The existing calculation is unchanged: `sign(fold change) * -log10(probability)`, replacing exact zero probabilities with `np.nextafter(0, 1)` (approximately `4.94e-324`). This produces absolute rank approximately `323.306` for a nonzero fold-change sign; zero fold change yields zero rank. Each preparation containing zero probabilities emits a warning with the input count. This is a numerical treatment of reported zeros, not evidence that their measured probability equals that floor. No threshold, censoring policy, or alternative floor is introduced.

6. **QC metadata:** Prepared DataFrames expose `attrs['ranking_metadata']`, also written under `ranking` in saved batch JSON sidecars. It records ordering, zero representation, duplicate policy, duplicate ID/row counts, opposing-sign and ambiguous-maximum ID counts, zero policy/replacement and input zero count. Duplicate counts are after multi-name handling but before collapse; duplicate row count includes every row belonging to a duplicated ID. Zero probability count is before expansion, so a zero-valued row split into two names counts once. Precomputed ranks report zero-probability policy as `not_applicable`. No-save calls keep these attrs without writing files. Per-collection metadata records the effective GSEApy `ascending` value.

7. **Expected numerical consequences:** Unique, untied ranks retain their numerical values and descending order. Tied ranks can change ES, NES and permutation-derived probabilities relative to older arbitrary orderings; that change is intentional. A synthetic 120-gene fixture (40 ranks each of 2, 0.5, -1; seed 6, 100 permutations, one thread) gave upper-set ES 0.9 versus 0.888889 under two old shuffled orders, and mixed-set ES 0.296354 versus 0.250471. Canonical preparation produced identical ES 1.0 and 0.214959 respectively across both shuffles. These fixture results illustrate sensitivity to tie ordering, not biological findings. Tests also compare all five enrichment metrics and every saved CSV/JSON byte across three shuffled signed-rank batches containing zero probabilities, tied zeros and an unequal opposing-sign duplicate.

8. **Interpretation of ties:** Alphabetical ordering supplies a reproducible convention, not biological evidence for ordering equally ranked features. If gene-set membership correlates with alphabetical IDs, choosing this convention can materially change enrichment, including its direction. A separate all-equal-rank 120-gene diagnostic changed ES from approximately -0.366667 to 1 for a term containing the first 30 alphabetical IDs. Treat such enrichment as sensitive to an unresolved rank tie, even though reruns are reproducible.

9. **Compatibility:** Function signatures, rank/result CSV schemas, collection names, return modes, the maximum-absolute aggregation rule for unambiguous duplicates, zero-probability floor and per-collection FDR scope are retained. New warnings, rejection of ambiguous duplicate maxima, canonical order, direct-call preservation of supplied order and sidecar ranking fields are intentional changes. Reproducibility claims apply to unchanged inputs/settings and the same software environment; they do not imply identical results across GSEApy releases or different seeds.
