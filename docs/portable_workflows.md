# Portable example workflows

1. **Entry points:** Run `python /path/to/checkout/examples/GSE68719/scripts/make_gseapy_tables.py --config /path/to/config.yaml` or `make_gseapy_dotplots.py` with the same option. Omitting `--config` selects the example's `config/config.yaml` beside the scripts. The checkout may be renamed, and the working directory may be unrelated. Source imports resolve from the script location. No package installation or new dependency is required beyond the existing runtime.

2. **Path contract:** Relative input, reference, output and plot-directory paths resolve against the selected YAML file's directory. Absolute paths remain valid. Copying a custom YAML elsewhere therefore requires adjusting its relative paths. The bundled configuration points to local example data/results and repository references. It no longer targets the unrelated ActioBio output directory. Existing files in that directory are not moved or deleted. Archived scripts under `scripts/old` and legacy top-level config blocks are not active entrypoints.

3. **Run control:** The `GSEApy_params.make_gseapy_tables_run_control.run_defined_gseapy_runs` flag gates named analyses. Each `defined_gseapy_runs` entry merges over `default_params`, including reference selection, input and output overrides. `run: false` skips a run before validating its inputs; omitted `run` retains the historical enabled behavior. Dotplots have `gseapy_dotplot_params.run`, also defaulting to enabled. The unimplemented all/selected differential-abundance modes now raise a clear error instead of silently doing nothing. Disabled workflows do not create output/log directories.

4. **Permutation settings:** The active bundled key is `permutation_num: 1000`, retaining the previous effective count. Legacy `gsea_permutation_num` is accepted. Run-level values take precedence over defaults even if the run uses the legacy spelling; within a single layer the canonical key wins. Scientific thresholds and ranking settings retain their configured values.

5. **Reference preflight:** Every enabled run's requested collection must match exactly one `.gmt` filename stem among its configured directories. Missing and ambiguous matches raise together before any enabled analysis or output creation. Repeated requested names are deduplicated in request order; repeated directory paths do not create false ambiguity. The bundled inventory currently resolves 70 unique names. With explicit `list_of_term_collections`, supply local GMT paths (relative to config or absolute); every file must exist. Optional `list_of_term_collection_names` must match the file count with nonempty labels. Explicit labels also apply to name-resolved collections. Remote library identifiers and mapping objects are not supported by this offline example CLI's explicit-path mode; use the Python wrapper for those inputs.

6. **Reference scope:** The requested `MGI_Mammalian_Phenotype_Level_4_2021` was changed to the approved available `MGI_Mammalian_Phenotype_Level_4_2024`. This is a reference-release change and can affect biological results. Existing human reference directories remain human: the historical mapping keys `enrichr_Hu_h2m` and `msigdb_Mm` are labels, not instructions to change species. No other collection or species policy was changed, and this work did not download or regenerate references.

7. **Outputs and logging:** Without a `results_dir` override, each analysis writes under `<repo_results_dir>/<DA_run_name>/<gseapy_run_name>`. A run/default `results_dir` is used directly. Logs are written under the effective output's `logs` directory and under `scripts/logs`. Dotplots read their configured run directories, skip `.rnk_df.csv`, and write to each run's `dotplots` directory. Missing directories and plotting errors now fail visibly instead of being silently skipped; empty directories still produce a warning. Existing output replacement behavior remains the responsibility of an actual workflow invocation; validation here used only temporary paths and mocked analysis/plot calls.

8. **Downloader:** `config/download_gseapy_gmt_files.py` imports the actual local `_gseapy_pre_rank_wrap` module. It remains a separate reference-download script with its existing repository-relative destinations and releases, not a YAML-driven example runner. Its offline test substitutes every remote download/conversion call. Running it normally still performs downloads and conversions; none were executed during this work.

9. **Verification limits:** Subprocess tests use a copied, renamed source layout, a separate configuration directory, an unrelated working directory, and mocked wrapper calls. They verify parameter forwarding, relative paths, enabled/disabled behavior, preflight before any analysis, inventory, plot output paths and downloader imports. No full biological workflow, reference refresh or existing-results rewrite was run. There is no Bash bootstrap or `local_env.sh` in this example; none was introduced.
