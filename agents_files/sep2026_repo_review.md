# Deep Repository Review — run_GSEApy_wrapper

1. **REVIEW CONTEXT:** This review covers the clean committed state at f0eff5d on main, reviewed on 2026-08-31. The repository is a GSEApy prerank wrapper with input-rank construction, Enrichr/MSigDB reference acquisition, human/mouse ortholog conversion, result serialization, plotting, and enrichment-network helpers. The review was read-only with respect to pipeline behavior; this report is the only added file.

2. **EXECUTIVE VERDICT:** The repository contains useful working analysis code and checked-in example outputs, but it is not yet reliable as a reusable scientific pipeline. Several confirmed defects can change scientific rankings, plot the wrong significance measure, make graph results depend on row order, or suppress missing result files while reporting success. The documented setup also cannot run from a fresh checkout. The highest priority is to lock down scientific policies for tied ranks, duplicate identifiers, species handling, orthologs, and zero p-values; add small deterministic regression tests; then fix the confirmed correctness defects without changing those policies implicitly.

3. **SEVERITY DEFINITIONS:** P1 means a defect can produce wrong or missing scientific output, silently ignore a requested model option, or block the documented workflow. P2 means a defect materially harms interpretation, scalability, portability, or failure visibility but usually requires a narrower trigger. P3 means maintainability, documentation, or repository-hygiene debt that should be addressed after correctness is protected.

4. **P1 — OPTIONAL COLLECTION NAMES ARE NOT ACTUALLY OPTIONAL, AND FAILURE IS SUPPRESSED:** [make_results_dataframe](../_gseapy_pre_rank_wrap.py#L144-L192) falls back to single_pre_res.gene_sets when collection_name is omitted. GSEApy exposes this as a dictionary for in-memory gene sets and as a path-like value for local GMTs. The dictionary case fails when concatenated with a string at line 168; an absolute GMT path can be interpolated into the output filename and imply nonexistent nested directories at lines 185–188. The broad catch at lines 190–192 suppresses either failure, while [the caller](../_gseapy_pre_rank_wrap.py#L330-L339) logs successful processing. A synthetic run returned normally and wrote only the rank CSV, not the result CSV. Derive a validated, sanitized name before analysis, re-raise schema/output errors, and log completion only after the expected artifact exists. Test dictionary and absolute-GMT inputs with omitted names.

5. **P1 — INVALID OR MISSING RANK INPUTS CAN BE ADMITTED, DROPPED, OR GIVEN THE WRONG DIRECTION:** [process_input_table](../_gseapy_pre_rank_wrap.py#L73-L102) stringifies feature identifiers before removing missing values. Under the pinned pandas 2.3.3 behavior, missing identifiers become literal values such as “nan”. Negative p-values become NaN ranks, p-values above 1 make negative -log10 values and can reverse a positive fold-change direction, and precomputed NaN or infinite ranks pass through. GSEApy then drops or rewrites some nonfinite values, so the analyzed set differs from the input without a hard failure. Validate required columns before string conversion; reject missing/blank identifiers, nonnumeric or nonfinite metrics, and p-values outside [0,1]; strip and filter split tokens; and define whether the two multi-name modes may be combined. Add focused tests for every invalid-input class.

6. **P1 — TIED RANKS ARE NOT FULLY ORDERED AND CAN CHANGE NES/FDR WITH THE SAME SEED:** Sorting at [lines 88–102](../_gseapy_pre_rank_wrap.py#L88-L102) has no stable secondary key, and GSEApy sorts the ranking again. A 120-gene synthetic diagnostic with identical rank values and seed but different input row order changed one term’s NES from -2.551320 to -2.446479 and another term’s FDR from 0.036269 to 0.030000. The latest commit makes result-table serialization deterministic after calculation, but it does not make the calculation deterministic when ranks tie. Choose a scientifically acceptable tie policy, fully order ranks using that policy, and configure GSEApy to preserve the prepared order. The regression must shuffle otherwise identical input rows and assert byte-identical rank tables plus identical ES, NES, p-value, FDR, and FWER values. GSEApy 1.1.11’s tie behavior is visible in its [Prerank implementation](https://github.com/zqfang/GSEApy/blob/v1.1.11/gseapy/gsea.py#L442-L488).

7. **P1 — REQUESTED GSEA MODEL OPTIONS ARE SILENTLY IGNORED:** [run_single_gsea_prerank](../_gseapy_pre_rank_wrap.py#L111-L140) accepts arbitrary keyword arguments at line 121 but never forwards them to gp.prerank at lines 123–133. For example, weight=0 is accepted and ignored, leaving GSEApy’s weighted default and changing the requested enrichment model without any warning. Either expose and forward a small vetted set of scientifically meaningful options such as weight and ascending, or remove the arbitrary keyword parameter so unsupported options fail immediately. A mock-based test should capture the exact gp.prerank call and verify every exposed option, especially weight=0.

8. **P1 — DUPLICATE SYMBOL COLLAPSE MAKES AN UNREPORTED DIRECTIONAL CHOICE:** The default duplicate handling at [lines 97–102](../_gseapy_pre_rank_wrap.py#L97-L102) keeps the row with the largest absolute rank. The committed GSE68719 input contains 57 duplicated symbols across 119 rows, and 24 duplicated symbols have estimates in opposing directions. The current policy silently chooses one direction and discards the rest; equal absolute values also lack an explicit deterministic tiebreaker. This is a scientific aggregation decision, not just data cleaning. Report duplicate and directional-conflict counts, require a unique upstream gene-level statistic or an explicitly approved aggregation policy, and record that policy in run metadata. Test concordant, discordant, and exactly tied duplicate symbols.

9. **P1 — SOURCE SPECIES IS NOT MODELED, SO MOUSE-NAMED LIBRARIES CAN BE USED AS HUMAN SETS OR CONVERTED AS IF THEY WERE HUMAN:** The bundled collection lists mix human and mouse resources, including both WikiPathways_2024_Human and WikiPathways_2024_Mouse at [lines 657–665](../_gseapy_pre_rank_wrap.py#L657-L665). The [download driver](../config/download_gseapy_gmt_files.py#L75-L105) fetches all named Enrichr libraries into the human directory and then applies human-to-mouse conversion to every file. Mouse-specific symbols can therefore match human ranks only by shared text, while already-mouse sets can be partially and incorrectly “converted” again. In the ACE mouse pathway, the conversion retained 6 of 8 listed symbols and dropped mouse-specific REN1 and AGTR1A. Add explicit source-organism metadata and allowlists, use native mouse sets unchanged, and convert only human-native sets. Test species-specific sentinel symbols.

10. **P1 — ORTHOLOG CONVERSION APPLIES AN UNDOCUMENTED MANY-TO-ONE/ONE-TO-MANY POLICY AND EMITS NO QC:** [_load_homolog_mapping](../_gseapy_pre_rank_wrap.py#L452-L463) converts the mapping table directly to a scalar dictionary, so conflicting duplicate source symbols use the final row. The checked-in h2m mapping has 14 source symbols with conflicting scalar targets and 1,110 rows listing multiple mouse targets; m2h has 2 conflicts and 1,198 multi-target rows. [convert_gmt_homologs](../_gseapy_pre_rank_wrap.py#L562-L575) silently drops unmapped genes, deduplicates targets, and retains empty terms without coverage reporting. Preserve the existing behavior until a scientific choice is approved, then explicitly define strict 1:1 versus expansion, reject conflicting source mappings, document mapping provenance/releases, and emit source, mapped, unmapped, collided, deduplicated, and empty-set counts for every library.

11. **P1 — ZERO FDR FLOORING CAN REVERSE SIGNIFICANCE ORDER IN DOTPLOTS:** [_apply_pvalue_zero_floor](../_gseapy_dot_plots.py#L31-L55) replaces zero values with 1/N. The committed outputs contain 7,579 zero FDRs and 3,235 positive FDRs below the default 1e-4 floor, so many true zeros become numerically less significant than positive FDRs. In one committed ARCHS4 table, 61 rows have zero FDR while two positive values are below 1e-4; after flooring, those positive values sort ahead of every zero. The default N=10,000 at [the public plotting APIs](../_gseapy_dot_plots.py#L95-L103) also disagrees with the example’s intended 1,000 permutations. Rank and filter on original values, and use a separate display-only transform or a floor strictly below every positive value. Test [0, 2e-6, 0.1] and assert the zero term remains first.

12. **P1 — pvalue_col CAN FLOOR ONE MEASURE WHILE THE PLOT USES ANOTHER:** [dotplot_from_table](../_gseapy_dot_plots.py#L105-L151) applies flooring to the requested pvalue_col but defaults the plotted column to “FDR q-val” whenever an fdr column exists at lines 147–150. The multi-table implementation repeats the defect at [lines 166–215](../_gseapy_dot_plots.py#L166-L215). A synthetic table with opposing nominal-p and FDR rankings and pvalue_col="pval" selected the FDR-best term. Raw GSEApy tables containing only “FDR q-val” also fail under the lowercase default, and mixed schemas are not safely coalesced. Resolve one canonical requested measure, convert it consistently to numeric, synchronize only its aliases, preserve an explicit column argument, and test wrapper-lowercase, raw-GSEApy, mixed, nominal-p, FDR, and custom-column cases.

13. **P1 — TOP-K GRAPH CONSTRUCTION IS ORDER-DEPENDENT:** [build_network_from_onehot](../_gseapy_post_process_helpers.py#L375-L402) trims each row of a symmetric similarity matrix independently, creating an asymmetric matrix, and then emits only entries with i < j. A neighbor retained only in the lower triangle is discarded. Reordering the same A/B/C incidence rows changed the edge set from AB alone to AB plus AC. Define whether top-k means mutual-kNN or union-kNN, apply deterministic tie-breaking, symmetrize accordingly, and extract edges only after symmetry is restored. Add a permutation-invariance regression comparing named edge sets for every row order.

14. **P1 — BETWEENNESS CENTRALITY TREATS SIMILARITY AS DISTANCE:** [the network metric block](../_gseapy_post_process_helpers.py#L417-L427) passes the similarity attribute named weight directly to NetworkX betweenness centrality. NetworkX interprets that value as a shortest-path distance, so stronger cooccurrence, cosine, or Jaccard edges are treated as longer paths. In a triangle with AB=0.9 and AC=BC=0.4, the current calculation assigns C betweenness 1.0; reciprocal-distance semantics assign 0. Retain weight as similarity for strength, eigenvector centrality, and community detection, add a separate positive distance attribute derived from an explicitly chosen transform, and test the triangle. Any transform choice should be documented because it changes reported network statistics.

15. **P1 — THE DOCUMENTED GMT DOWNLOADER CANNOT START:** [config/download_gseapy_gmt_files.py](../config/download_gseapy_gmt_files.py#L9-L24) appends the repository root and imports gseapy_pre_rank_wrap, but the only implementation is named _gseapy_pre_rank_wrap.py. Running the documented command from [README lines 11–16](../README.md#L11-L16) in a GSEApy-capable environment raises ModuleNotFoundError before any download begins. Use a real package import and installable package context, then test the subprocess from both the repository root and an unrelated working directory with all remote calls mocked.

16. **P1 — THE ACTIVE EXAMPLE IS TIED TO ONE UBUNTU CHECKOUT AND INCLUDES AN UNRELATED PROJECT PATH:** [examples/GSE68719/config/config.yaml](../examples/GSE68719/config/config.yaml#L4-L24) hard-codes /home/ubuntu paths for inputs, references, and outputs; [lines 111–137](../examples/GSE68719/config/config.yaml#L111-L137) repeat them and include an ActioBio TRPV4 project outside this repository. The active scripts consume those values and create output directories before meaningful validation. None of the configured absolute paths exists in this checkout. Resolve repository assets relative to the config or repository root, accept an explicit config path, remove the unrelated project entry, and test a copied checkout from a temporary path and arbitrary working directory.

17. **P1 — A REQUESTED BIOLOGICAL COLLECTION IS SILENTLY OMITTED:** [the example config](../examples/GSE68719/config/config.yaml#L25-L101) requests 70 unique collections, including MGI_Mammalian_Phenotype_Level_4_2021 at line 48, while the bundled reference is the 2024 collection. [The runner](../examples/GSE68719/scripts/make_gseapy_tables.py#L162-L181) filters whatever files happen to exist and never checks that every request resolved. Only 69 unique requested collections resolve, and each committed analysis has 69 collection outputs. Add a preflight that requires an exact, unique request-to-file mapping and fails before analysis. Choosing 2021 versus 2024 is a scientific reference update and requires explicit approval; tests should cover missing, duplicated, and ambiguous collection names.

18. **P1 — REFERENCE REFRESHES ARE NEITHER ATOMIC NOR FULLY REPRODUCIBLE:** [the download driver](../config/download_gseapy_gmt_files.py#L75-L125) queries live Enrichr and versioned MSigDB services and overwrites checked-in directories. [_write_gmt_dict](../_gseapy_pre_rank_wrap.py#L437-L449) writes target files directly, and [make_gmts_from_Msigdb](../_gseapy_pre_rank_wrap.py#L508-L531) omits dbver from filenames despite its docstring, allowing another release to overwrite the same path. There is no source URL, retrieval timestamp, package version, response hash, mapping hash, or snapshot manifest, and interruption can leave a mixed old/new snapshot. Download to staging, validate the complete requested inventory and gene-set structure, write a machine-readable provenance/checksum manifest, and atomically publish only a complete snapshot. Test interruption safety and byte-identical repeated snapshots with mocked services.

19. **P2 — CUSTOM TERM LABELS ARE NOT FORWARDED, AND TRUNCATION COLLAPSES DISTINCT PATHWAYS:** [dotplot_from_table](../_gseapy_dot_plots.py#L119-L151) uses term_label_col for preprocessing but never passes it to GSEApy as y; the multi-table path repeats this at [lines 182–215](../_gseapy_dot_plots.py#L182-L215). Both functions truncate the categorical values themselves, so two distinct pathways sharing a prefix collapse onto one y coordinate; ordered mode additionally deduplicates the shortened names and may hide rows. Set y from term_label_col unless an explicit conflict is rejected, preserve full category keys, and truncate only rendered tick labels or disambiguate them deterministically. Test actual tick labels and two long terms with the same prefix.

20. **P2 — FDR SCOPE IS COLLECTION-SPECIFIC, BUT OUTPUT AND LOGGING CAN BE READ AS GLOBAL SIGNIFICANCE:** [The multi-collection loop](../_gseapy_pre_rank_wrap.py#L296-L337) runs GSEA separately for each collection, so each FDR is defined relative to that collection. Combining files later does not create one globally adjusted family. The completion log at line 337 also calls every row passing only a matched-gene-count filter “significant,” although no p-value or FDR threshold is applied. Document and serialize the adjustment-family identifier, rename the log to reported/tested terms, and decide explicitly whether the inferential family is per collection or global. If a global family is intended, that is a scientific workflow change and must be designed and approved rather than inferred.

21. **P2 — EXACT ZERO INPUT P-VALUES CAN DOMINATE WEIGHTED GSEA:** [Rank construction](../_gseapy_pre_rank_wrap.py#L84-L88) replaces zero with the smallest positive subnormal float, producing rank magnitude about 323.306. Because the wrapper currently uses weighted GSEA, a single underflowed p-value can dominate the running sum, while multiple zeros create the tie instability described above. Make the zero-input policy explicit and record it in metadata; possible alternatives such as a dataset-derived floor require scientific approval. Test zeros beside very small nonzero probabilities and verify the approved policy exactly.

22. **P2 — PERMUTATION SETTINGS CAN PRODUCE MISLEADING INFERENTIAL FIELDS:** The public defaults are 100 permutations in [run_single_gsea_prerank](../_gseapy_pre_rank_wrap.py#L111-L129) and [the multi-collection wrapper](../_gseapy_pre_rank_wrap.py#L214-L220), limiting nominal resolution. Zero or negative values are not rejected; GSEApy can then return zero-valued NES/p-value/FDR fields that look significant rather than unavailable. Validate positive counts for inferential runs, or expose an explicit ES-only mode that marks inferential fields missing. Record the count in every result manifest. Changing the default count is a scientific/runtime policy decision, so first add tests for zero, negative, low, and configured counts without silently changing 100.

23. **P2 — MULTI-COLLECTION IN-MEMORY RETURN EXPOSES ONLY THE LAST RESULT:** [The loop](../_gseapy_pre_rank_wrap.py#L296-L320) overwrites single_pre_res for every collection, and [lines 341–342](../_gseapy_pre_rank_wrap.py#L341-L342) return only the final value. With save_table_output=False, all earlier results become inaccessible; an empty list can leave the local variable undefined. Validate a nonempty collection list and either return an insertion-ordered mapping in a new explicit mode or reject return_single_pre_res=True for multiple collections while preserving the current public default. Test zero, one, and multiple collections.

24. **P2 — MISSING METABOLITE ANNOTATIONS BECOME A REAL “nan” MEMBER:** [metabolon_chemical_annotation_to_pathway_table](../_gseapy_pre_rank_wrap.py#L416-L429) casts every annotation column to string before aggregation, converting missing CHEM_ID, HMDB, and other identifiers into the literal “nan”. The downstream GMT conversion can write that value as a member, and it can even match a rank identifier created from a missing feature. Remove missing and blank values per selected identifier column before string conversion and aggregation, then deduplicate deterministically. A synthetic missing CHEM_ID currently yields ["1.0", "nan"]; retain this as a failing regression.

25. **P2 — LEADING-EDGE DICTIONARY CONSTRUCTION HAS CATASTROPHIC I/O SCALING:** [make_dictionary_of_leading_edge_genes](../_gseapy_post_process_helpers.py#L84-L100) reads the CSV once and then calls a helper that rereads it once per term. The committed 28,411-row, approximately 53 MiB MSigDB result implies 28,412 parses and roughly 1.4–1.5 TiB of file reads for the default all-term call. Split the already-loaded lead_genes series directly and construct the mapping in one pass. Test exact output and monkeypatch pd.read_csv to assert one call.

26. **P2 — NETWORK HELPERS ARE NOT MEMORY-BOUNDED FOR LARGE ENRICHMENT SETS:** Dense one-hot construction occurs at [lines 213–226](../_gseapy_post_process_helpers.py#L213-L226), another dense copy is made at [lines 362–365](../_gseapy_post_process_helpers.py#L362-L365), full pairwise similarity is built before top-k, Pearson explicitly calls toarray at [lines 305–313](../_gseapy_post_process_helpers.py#L305-L313), and exact betweenness is unbounded. This conflicts with the repository’s large checked-in collections. Keep incidence data sparse end-to-end, select bounded neighbors before materializing all pairs, bound or reject dense Pearson and exact centrality above documented limits, and handle zero/one-node axes. Add sparse scale tests with a memory ceiling.

27. **P2 — CONFIGURATION CONTROLS ARE IGNORED OR UNIMPLEMENTED:** [config line 11](../examples/GSE68719/config/config.yaml#L9-L20) names gsea_permutation_num, but [the runner](../examples/GSE68719/scripts/make_gseapy_tables.py#L214-L229) reads permutation_num. The current fallback happens to equal 1,000, so changing the visible config key has no effect. The “all” and “selected” run modes configured at lines 102–107 are silent pass branches at [runner lines 188–195](../examples/GSE68719/scripts/make_gseapy_tables.py#L188-L195). Align the key while preserving the current effective default, and either implement those modes or reject them clearly. Mock the wrapper and assert every nondefault config value and run-control mode reaches the intended call.

28. **P2 — PACKAGE AND ENVIRONMENT CONTRACTS ARE INCOMPLETE:** There is no pyproject.toml, setup metadata, console entry point, or version metadata, so the package imports only when its parent directory is already on sys.path. The active scripts manually mutate sys.path. [The advertised environment](../config/env_GSEApy.yaml#L1-L229) is an exported Linux-specific environment with exact build strings and a /home/ubuntu prefix rather than a portable direct-dependency specification. The graph helpers require NetworkX, and the Excel helper needs an Excel engine, but neither is declared. Add minimal packaging and a supported module/command entry point; define one canonical direct-dependency environment plus platform locks, or explicitly state Linux-only support. New dependencies or optional extras require separate approval.

29. **P2 — DOWNLOAD AND BATCH-PLOTTING FAILURES ARE TOO EASY TO MISS:** [The GEO downloader](../examples/GSE68719/config/download_gse_data.py#L34-L56) trusts any nonempty existing file, uses no timeout/checksum/content validation, and does not validate gzip integrity before accepting an artifact, although its partial-file atomic replace is a good base. [The dotplot batch loop](../examples/GSE68719/scripts/make_gseapy_dotplots.py#L116-L141) catches every unexpected exception and exits successfully even if no figure was produced. Add a source manifest with size/SHA-256, timeout and gzip validation, plus explicit batch failure accounting and nonzero exit on failed required outputs. Test corrupt existing files, truncated downloads, empty directories, malformed tables, and mixed valid/invalid batches.

30. **P2 — THIRD-PARTY DATA PROVENANCE AND LICENSE NOTICES ARE ABSENT:** The software [LICENSE](../LICENSE) is MIT, but [README](../README.md) does not identify licenses, citations, releases, or redistribution conditions for bundled Enrichr, MSigDB, KEGG legacy, BioCarta, GEO, and ortholog-mapping data. This review does not conclude that redistribution is impermissible; it identifies an unaudited compliance and reproducibility risk. Add a DATA_LICENSES.md or equivalent manifest with source, release, retrieval date, checksum, citation, and applicable terms for every bundled collection, and verify those terms before further publication. Start with the [official MSigDB license terms](https://www.gsea-msigdb.org/gsea/msigdb_license_terms.jsp) and [collection license overview](https://www.gsea-msigdb.org/gsea/license_terms_list.jsp).

31. **P2 — GENERATED AND DOWNLOADABLE ARTIFACTS DOMINATE THE REPOSITORY:** Git tracks 666 files totaling about 1.82 GB; data contributes about 1.25 GB, examples about 568 MB, and the Git pack is about 700 MiB. Forty-eight files are at least 10 MiB, and two result CSVs are about 55 MiB. No tracked blob exceeds GitHub’s 100 MiB limit, but clone, CI, and review cost are severe. Three differently named GSE68719 differential-expression files are byte-identical, including one plain-text file with a “_gz” suffix. Keep compact deterministic smoke fixtures and expected summaries in Git, and move full immutable snapshots/results to versioned releases or a data registry with hashes. Any history rewrite is destructive and requires a separate approved migration and backup.

32. **P2 — THE REPRODUCIBILITY CLAIM HAS NO AUTOMATED EVIDENCE:** [README lines 1–3](../README.md#L1-L3) claim reproducible FDR, but the repository has no tests, CI configuration, deterministic fixture harness, or run manifest. Output tables do not record package versions, commit identity, input hash, GMT hash, ortholog-map hash, or full parameters. Add a tiny synthetic fixture that completes quickly, run it twice, compare rank/result bytes and aligned numerical columns, and retain a structured manifest. Add focused unit tests for every P1 defect before running the full public example.

33. **P3 — DOCUMENTATION AND PRIVATE/PUBLIC BOUNDARIES ARE STALE:** [README’s tree](../README.md#L18-L62) names nonexistent gseapy_pre_rank_wrap.py and make_gsea_tables.py paths and does not provide an end-to-end analysis or plotting command. [Package exports](../__init__.py#L1-L24) expose prerank and dotplot helpers but not post-processing/network helpers, while the latter live in an underscore-prefixed module and configure global logging on import. Decide whether those helpers are supported API or archival experiments before exporting or expanding dependencies. Replace the hand-written tree with one tested minimal workflow, supported platform statement, config schema, expected outputs, references, and citations.

34. **POSITIVE OBSERVATIONS:** The working tree was clean and main matched origin/main at review start. YAML uses safe loading, the GEO downloader uses HTTPS and a temporary file before replacement, directory-level GMT conversion sorts input filenames, term keys are sorted when writing GMTs, and the latest commit adds a complete deterministic sort for serialized result rows tied on FDR. Python syntax compiles under both 3.10 and 3.13, and all YAML files parse. No obvious credentials, shell=True execution, or secret material were found in the inspected source/configuration.

35. **VALIDATION PERFORMED:** The review inspected all active Python modules, package exports, four YAML files, README, license, gitignore, recent history, example inputs/results, mapping tables, representative native/converted GMTs, tracked sizes, and the absence of tests/CI/packaging metadata. Targeted diagnostics used pandas 2.3.3 and a local GSEApy 1.1.13 environment, with relevant pinned GSEApy 1.1.11 behavior checked against source and plotting behavior. Confirmed reproductions include the broken download import, silent missing result CSV, invalid-p direction reversal, literal missing identifiers, order-dependent top-k edges, ignored nominal-p plot selection, zero-FDR reordering, and metabolite “nan” membership. All temporary artifacts were outside the repository.

36. **LIMITATIONS:** The declared Linux Conda environment was not recreated, live reference downloads were not performed, and the full 1,000-permutation example was not rerun because this was a read-only review and the active config targets absent /home/ubuntu paths. Therefore local green syntax/YAML checks are not target-environment numerical proof. The intended duplicate-gene policy, rank-tie policy, source-species policy, ortholog policy, zero-p-value policy, and FDR adjustment family are undocumented and cannot be safely inferred.

37. **REMEDIATION PHASE 0 — SCIENTIFIC DECISIONS:** Before changing numerical behavior, explicitly approve and document six policies: how tied ranks are ordered, how duplicate symbols are aggregated, how source and target species are represented, how one-to-many orthologs are handled, how zero input p-values are ranked, and whether FDR families are per collection or global. Preserve current defaults until each decision is made.

38. **REMEDIATION PHASE 1 — CHARACTERIZATION AND REGRESSION TESTS:** Add a minimal install/import smoke test and deterministic synthetic fixtures first. Encode the confirmed failures for omitted collection names, invalid ranks, tied-row shuffles, ignored weight, duplicate-direction conflicts, species sentinels, ortholog conflicts, zero-FDR order, nominal-p plotting, custom labels, top-k permutation invariance, betweenness distance, single-read leading-edge parsing, and config propagation. Keep fixtures small and schema-compatible.

39. **REMEDIATION PHASE 2 — CORRECTNESS FIXES:** In separate reviewable commits, fix result failure propagation and collection naming; validate input ranks; forward or reject model options; implement approved tie/duplicate/species/ortholog policies; repair plot measure resolution and label identity; symmetrize top-k graphs; and separate similarity from distance. Do not combine these with formatting or unrelated refactoring.

40. **REMEDIATION PHASE 3 — PORTABILITY AND REPRODUCIBILITY:** Repair the downloader import, add minimal packaging/entry points, resolve config paths relative to the repository, validate the complete requested library inventory, make snapshots staged and atomic, and emit run/reference manifests with checksums and versions. Preserve scientific thresholds, seeds, and effective permutation defaults unless separately approved.

41. **REMEDIATION PHASE 4 — SCALE AND REPOSITORY HYGIENE:** Make post-processing sparse and one-pass, project only plotting columns, define supported graph-size limits, add CI, document data licenses, remove redundant example artifacts in a separate cleanup, and migrate full data/results out of Git only through an explicitly approved, recoverable publication plan. No history rewrite should be bundled with correctness work.
