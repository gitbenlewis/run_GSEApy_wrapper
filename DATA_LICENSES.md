# Reference data provenance and notices

1. **Scope and review date:** Reviewed 2026-10-29. The repository software license does not establish a license for bundled GMT collections or mapping tables. This records checked primary sources and unresolved provenance; it is not blanket clearance to redistribute the reference tree. No reference files were downloaded, replaced or republished during Plan05.

2. **MSigDB:** Configured acquisition releases remain 2025.1.Hs and 2025.1.Mm. The official [license terms](https://www.gsea-msigdb.org/gsea/msigdb_license_terms.jsp) state CC BY 4.0 for recent MSigDB releases with additional conditions for specific collections. KEGG MEDICUS has CC BY-SA 4.0 terms; KEGG LEGACY and BioCarta carry additional notices/conditions. Preserve source attribution, collection-specific notices and modification history. An aggregate collection may include these subsets. Do not label all derived MSigDB files simply MIT or unrestricted.

3. **Species evidence:** The [MSigDB FAQ](https://docs.gsea-msigdb.org/MSigDB/MSigDB_FAQ/) identifies separate human and mouse databases using their respective approved gene symbols. It also explains release-specific identifier mappings. This supports species declarations for newly acquired, explicitly versioned MSigDB resources; it does not retrospectively prove which release generated a particular checked-in file. Study organism and delivered identifier organism must be recorded separately.

4. **Enrichr:** The [official resource](https://maayanlab.cloud/Enrichr/) requests citation and lists libraries drawn from multiple upstream resources. Cite Chen et al. (2013), Kuleshov et al. (2016), and/or Xie et al. (2021), as applicable; links are supplied on that page. Availability through Enrichr is not treated here as evidence of a universal redistribution license or of identifier species. Each requested library needs explicit species evidence and source-specific license/provenance review. All otherwise-unlisted bundled Enrichr libraries remain unresolved for redistribution in this review.

5. **Reactome:** The current [official license](https://reactome.org/license) distinguishes data (CC0) from illustrations and software. Retain source/release and transformation records for Reactome-derived GMTs. These current upstream terms do not independently identify the origin or release of historical local copies.

6. **KEGG:** The [official notice](https://www.genome.jp/kegg/legal.html) describes academic website use, service-provider licensing, and commercial licensing. No blanket redistribution permission for bundled KEGG-derived GMTs was established. Resolve applicable terms for the precise acquisition route and intended use before publishing new snapshots; MSigDB-specific conditions are separately documented above.

7. **WikiPathways:** The production terms page at https://www.wikipathways.org/terms.html returned HTTP 403 during this review. Search results exposed a sandbox CC0 statement, but it was not substituted for verified production terms. The applicable terms for the exact bundled derivative remain unresolved here.

8. **Ortholog tables and historical snapshots:** The CSV schema exposes Ensembl-like gene IDs and scalar/complete target symbol columns, but the inspected repository does not establish the mapping provider, release, retrieval date, query settings or redistribution license. Do not infer these from identifier syntax. Record unknown fields explicitly. Newly calculated hashes establish present file identity, not historical provenance. The known contradictory mapping records must be resolved upstream before the approved converter can use these tables.

9. **Disposition:** Offline implementation and synthetic tests can proceed. Existing files remain untouched. Before a new data release, complete per-resource source URL, identifier-species evidence, release, acquisition date where actually observed, applicable terms/notices and mapping provenance. Unknowns must remain visible in manifests; scientific species uncertainty blocks routing, while unresolved redistribution terms block claiming publication clearance. No data publication is authorized by Plan05's implementation approval.
